## 新增需求

### Requirement: 全局开关

系统应提供单一开关来启用或禁用所有拦截。禁用时，所有 DNR 规则应被清除。重新启用时，所有活跃规则应被重新应用。

#### Scenario: 禁用所有拦截

- **WHEN** 用户将全局开关拨到 OFF
- **THEN** 所有 DNR 规则被清除，没有网站被拦截

#### Scenario: 重新启用所有拦截

- **WHEN** 用户将全局开关拨到 ON
- **THEN** 所有启用的规则作为 DNR 规则重新应用

### Requirement: 自动恢复定时器

用户手动禁用拦截时，系统应支持一个自动恢复定时器，在 N 分钟后重新启用拦截。用户应能配置自动恢复时长。

#### Scenario: 超时后自动恢复

- **WHEN** 用户禁用拦截并设置 30 分钟自动恢复
- **THEN** 30 分钟后，拦截自动重新启用

#### Scenario: 取消自动恢复

- **WHEN** 用户在自动恢复定时器触发前手动重新启用拦截
- **THEN** 自动恢复定时器被取消

### Requirement: 快捷添加当前站点

系统应在 popup 中显示当前活动标签页的域名，并允许用户将其添加为拦截规则。用户应能在添加前选择分类并可选填写自定义信息。

#### Scenario: 快捷添加并选择分类

- **WHEN** 用户在 `reddit.com` 上，打开 popup，选择分类"新闻"，点击"拦截此站点"
- **THEN** 创建一个分类为"新闻"的 `reddit.com` 域名拦截规则

#### Scenario: 快捷添加自定义信息

- **WHEN** 用户添加站点时附带自定义信息 "现在不行！"
- **THEN** 规则被创建，拦截页面显示 "现在不行！"

#### Scenario: 站点已被拦截

- **WHEN** 用户尝试快捷添加一个已有拦截规则的站点
- **THEN** 系统显示"已拦截"而非添加按钮

### Requirement: Popup 信息面板

Popup 应显示：今日拦截次数、活跃规则数量、活跃解锁的剩余时间（如有）、下次调度启停时间（如调度已启用）。

#### Scenario: 显示今日统计

- **WHEN** 用户打开 popup，今天已拦截 42 个网站
- **THEN** popup 显示 "今日拦截 42 次"

#### Scenario: 显示活跃解锁倒计时

- **WHEN** 某临时解锁还有 3 分钟剩余
- **THEN** popup 显示倒计时 "剩余 3:00"

#### Scenario: 显示下次调度变更

- **WHEN** 调度已启用，下一个拦截时段从下午 2 点开始
- **THEN** popup 显示 "下次拦截开始于 14:00"
